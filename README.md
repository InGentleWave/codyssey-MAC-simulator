# Mini NPU Simulator

패턴과 필터를 같은 위치끼리 곱해 더하는 MAC(Multiply-Accumulate) 점수로 십자가(Cross)와 X를 판별하는 Python 콘솔 프로그램입니다(코디세이 E1_3 AI Like 계산기).

## 실행 방법

### 준비

- Python 3.8 이상이 필요합니다. 표준 라이브러리만 사용하므로 별도 패키지 설치는 없습니다.
- 폴더 구조

```
E1_3/
├── main.py                    진입점
├── data.json                  미션 제공 데이터(main.py와 같은 폴더)
├── README.md
├── samples/
│   └── data_invalid.json      의도적 오류 사본(재현성 확인용)
└── src/                       기능 모듈
```

### 실행 명령

| 환경 | 기본 실행 | 다른 데이터 파일로 실행 |
|---|---|---|
| Windows (PowerShell/cmd) | `python main.py` 또는 `py main.py` | `python main.py samples/data_invalid.json` |
| WSL Ubuntu | `python3 main.py` | `python3 main.py samples/data_invalid.json` |

- 기본 data.json은 main.py가 있는 폴더에서 찾으므로 어느 폴더에서 실행해도 됩니다.
- 실행 인자로 준 경로는 현재 폴더를 기준으로 해석합니다. 실행 인자는 모드 2에서만 사용합니다.

### 모드 선택

| 번호 | 모드 | 동작 |
|---|---|---|
| 1 | 사용자 입력 (3x3) | 필터 A, B와 패턴을 한 줄에 숫자 3개씩 공백으로 구분해 입력 → 두 점수, 판정(A/B/판정 불가), 성능 분석 |
| 2 | data.json 분석 | 필터 로드 → 케이스별 판정과 PASS/FAIL → 성능 분석(3×3, 5×5, 13×13, 25×25) → 결과 요약 |
| 3 | 패턴 생성기 (N×N) | 홀수 N(3~25) 입력 → Cross/X 필터 생성 → 패턴 종류 선택 → 판정, PASS/FAIL, 성능 분석(보너스) |

### 종료

- 입력 종료(EOF): Windows는 Ctrl+Z 입력 후 Enter, WSL Ubuntu는 빈 줄에서 Ctrl+D. 안내 문구를 출력하고 바로 종료합니다.
- 강제 중단: Ctrl+C. 안내 문구를 출력하고 바로 종료합니다.
- 데이터 로드 실패(파일 없음, JSON 문법 오류): 사유를 출력하고 엔터 입력 후 종료합니다.
- 예상치 못한 오류: 오류 종류·메시지와 traceback을 출력하고 엔터 입력 후 종료합니다(종료 코드 1).

### 라벨 정규화

- 프로그램 안에서는 표준 라벨 Cross, X만 씁니다. 동점일 때의 판정값 UNDECIDED는 라벨이 아니라 판정 상태입니다.
- `src/labels.py`의 별칭표 한 곳에서 '+'·'cross' → Cross, 'x' → X로 바꿉니다. 앞뒤 공백을 지우고 소문자로 바꾼 뒤 조회하므로 'X', 'Cross', ' + '도 같은 결과가 나옵니다.
- data.json의 expected 값과 필터 하위 키에 같은 함수를 적용합니다. 콘솔 출력과 PASS/FAIL 비교는 표준 라벨로만 합니다.
- 별칭표에 없는 라벨은 해당 케이스를 [라벨] 분류로 FAIL 처리합니다.

### MAC 연산

- `mac()`은 행 우선 이중 반복문으로 같은 위치의 값을 `Matrix.get()`으로 읽어 곱하고 0.0부터 더합니다. NumPy 같은 외부 라이브러리와 `sum()`, `math.fsum()`은 쓰지 않습니다.
- 누적 순서를 행 우선으로 고정해, 보너스 B1의 1차원 MAC과 결과가 완전히 같도록 했습니다.

### 동점 처리 정책(epsilon)

- `abs(a - b) < 1e-9`이면 동점으로 보고 판정을 UNDECIDED로 합니다(모드 1은 "판정 불가"로 표시). 동점 검사를 대소 비교보다 먼저 합니다.
- 상대 허용오차를 쓰는 `math.isclose` 대신 미션 권장식(절대 허용오차, `<` 비교)을 그대로 씁니다.
- 동점이면 두 점수의 차이값을 함께 출력합니다. 점수는 반올림하지 않은 기본 float 표기로 출력해, 아주 작은 차이도 화면에서 확인할 수 있습니다.

### 입력 검증과 오류 처리

- 모드 1: 행렬 3줄을 모두 받은 뒤 검증합니다. 열 수 불일치, 숫자 파싱 실패, NaN/Infinity가 있으면 안내 문구와 줄별 사유를 출력하고 그 행렬 3줄 전체를 다시 입력받습니다.
- 모드 2: 케이스마다 키 형식, 필터 존재, input/expected 필드, 크기, 값, 라벨을 검증합니다. 실패해도 프로그램을 멈추지 않고 해당 케이스만 FAIL로 기록합니다.
- 실패 사유는 다섯 가지로 분류합니다.

| 분류 | 발생 조건 | 원인 구분 |
|---|---|---|
| 스키마 | 키 형식 오류, 필드 누락, 숫자가 아닌 값·비유한값, 필터 없음 | 데이터/스키마 |
| 크기 | 행·열 수 불일치, 패턴·필터 크기 불일치 | 데이터/스키마 |
| 라벨 | 별칭표에 없는 expected | 데이터/스키마 |
| 동점 | 두 점수 차이 < 1e-9 → UNDECIDED | 수치 비교 |
| 불일치 | 판정(Cross/X)이 expected와 다름 | 로직 또는 라벨 데이터 |

### 성능 측정

- `time.perf_counter()`로 MAC 호출 10회 전체 구간을 재고 10으로 나눠 평균(ms)을 냅니다. 측정 구간에는 입력·출력·파일 읽기가 들어가지 않습니다.
- 측정 단위는 "패턴 1개 × 필터 1개의 MAC 1회"이며 표의 연산 횟수 N²와 대응합니다.
- 모드 2의 5×5, 13×13, 25×25는 data.json에서 해당 크기의 첫 유효 패턴과 Cross 필터로 측정합니다. data.json에 없는 3×3은 생성한 십자가 패턴으로 측정합니다.

### 보너스

- B1(1D 최적화): `Matrix.to_flat()`으로 길이 N²의 1차원 리스트를 만들고, `mac_flat()`이 단일 반복문으로 계산합니다. 1차원 변환은 측정 구간 밖에서 한 번만 하고, 2D와 같은 입력·같은 반복 횟수로 비교합니다. 두 결과가 완전히 같은지도 표에 표시합니다.
- B2(패턴 생성기): `make_cross()`, `make_x()`가 홀수 N의 십자가·X 패턴을 만듭니다. 모드 3은 모드 1의 처리 흐름(점수 → 판정 → 성능 분석)을 그대로 쓰고, 고른 패턴 종류를 expected로 삼아 PASS/FAIL까지 표시합니다. 모드 2의 3×3 측정 데이터도 이 생성기로 만듭니다.

### 실패 원인 분석

- data.json의 FAIL 3건(size_5_1, size_13_2, size_25_1)은 모두 [동점] 분류입니다.
- 원인은 필터 가중치에 있습니다. 세 케이스 모두 오답 필터의 중심 가중치가 정답 필터의 가중치 합과 같아서, 실수 계산으로는 두 점수가 정확히 같습니다.
  - size_5_1: Cross 필터 중심 0.9 × 1 = 0.9, X 필터 0.1 × 9칸 = 0.9
  - size_13_2: Cross 필터 0.3 × 25칸 = 7.5, X 필터 중심 7.5 × 1 = 7.5
  - size_25_1: Cross 필터 중심 4.9 × 1 = 4.9, X 필터 0.1 × 49칸 = 4.9
- 0.1, 0.3 같은 값은 2진수 부동소수점으로 정확히 표현되지 않아, 여러 번 더하면 마지막 자릿수에 오차가 쌓입니다. 그래서 출력된 두 점수는 마지막 자릿수만 다릅니다(위 실행 결과 표). 이 차이는 1e-9보다 훨씬 작습니다.
- epsilon 없이 `>`로 비교했다면 이 미세한 차이가 어느 쪽으로 났는지에 따라 판정이 우연히 정해집니다. 그러면 결과가 데이터의 실제 성질(동점)을 보여 주지 못합니다.
- epsilon 정책을 적용하면 세 케이스가 일관되게 UNDECIDED가 되고, expected(Cross 또는 X)와 다르므로 동점 규칙에 따라 FAIL입니다.
- 따라서 이 FAIL은 로직 오류가 아니라 "필터 가중치가 만든 수학적 동점(데이터 쪽 원인)"을 "동점 처리 규칙(수치 비교 정책)"이 정상적으로 잡아낸 결과입니다. 03의 3분류로는 수치 비교 문제이고, 근본 원인은 데이터에 있습니다.
- 나머지 3건(size_5_2, size_13_1, size_25_2)은 정답 필터 점수가 크게 앞서므로 PASS입니다.
- 라벨 정규화를 하지 않았다면 판정('Cross', 'X')과 expected('+', 'x')가 문자열로 달라서 6건 모두 [불일치] FAIL이 됩니다. 정규화가 이 3건을 PASS로 만든 요인입니다.
- 비교 정책의 한계: 절대 허용오차 1e-9는 이 데이터처럼 점수 규모가 작을 때 알맞습니다. 점수가 2^23(약 8.4×10⁶) 이상이면 인접한 double 값 사이의 간격이 1e-9보다 커져, 사실상 두 값이 완전히 같을 때만 동점이 됩니다(계산값). 점수 규모가 큰 데이터라면 상대 허용오차를 함께 쓰는 정책이 필요합니다.

### 성능 분석과 시간 복잡도

**크기별 평균 시간(모드 2, 10회 반복 평균)**

| 크기 | 연산 횟수(N²) | 평균 시간(ms) | 3×3 대비 연산 횟수 비 | 3×3 대비 시간 비 |
|---|---|---|---|---|
| 3×3 | 9 | [기입] | 1.0 | 1.0 |
| 5×5 | 25 | [기입] | 2.8 | [기입] |
| 13×13 | 169 | [기입] | 18.8 | [기입] |
| 25×25 | 625 | [기입] | 69.4 | [기입] |

- MAC 1회는 N×N 칸마다 곱셈 1번과 덧셈 1번을 하므로 연산 횟수는 N²이고, 시간 복잡도는 O(N²)입니다. 케이스 하나는 필터 2개를 계산하므로 2N²번이고, 케이스 P개를 판정하면 O(P·N²)입니다.
- O(N²)는 한 변의 길이 N을 기준으로 한 표현입니다. 원소 수 M = N²를 기준으로 보면 O(M), 즉 입력 크기에 선형입니다.
